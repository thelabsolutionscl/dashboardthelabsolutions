# Signed operator CRM and supplier read scope

The Access `operator` role previously inherited the generic Airtable GET path for every recognized non-finance table. Since actual Clientes, Cotizaciones and Pedidos contain bank accounts, real margin, raw proposals, tax references, private AI finance reports and material/labor cost columns, denying the separate Facturas table was **not sufficient** to protect financial data.

This change stages a separate, server-side GET projection for **signed operator sessions** on Clientes, Cotizaciones, Pedidos and Proveedores. The catalogs were compared with the current Airtable schema. The operator may still see company-wide operational CRM details, including normal quotation totals and order sales prices needed for production and quoting, but does not receive bank details, actual margins, real production costs, fiscal document identifiers, unrestricted proposal JSON or unknown future columns. The proxy requests only approved columns upstream for lists and constructs a fresh, approved response for both lists and GET by record ID.

As for the signed viewer, these routes reject arbitrary `filterByFormula`, views, sort fields, unapproved field projections and unknown query arguments to prevent inference of hidden values through result counts and ordering. Paging remains bounded. Owner-based isolation is specific to `sales`, not this company-wide `operator` role.

**Scope and rollout limitations:** operator reads outside those four tables retain their previous access. Operator CRM POST, PATCH and DELETE permissions have **not** been made safe by this read-only change; the next P0 task is field-level mutation checks, owner/relation safeguards and delete restrictions for non-administrators. Other tables, such as Monitor Sistema and future Inventario, need a separate classification of notes/secrets and production operational requirements. Existing non-finance fields and unrestricted notes can contain sensitive information if staff paste it there; a field catalog cannot retrospectively sanitize free text.

Legacy APP_KEY mode remains as before until the coordinated Cloudflare Access and DNS cutover. UI workflows using unapproved hidden columns or server-side formulas must be adapted/tested before enabling real operator sessions. `finance` and `admin` preserve their authorized complete views. This code does not authorize enabling `ACCESS_SALES_WRITES_ENABLED` or imply that external Make integrations have been audited.
